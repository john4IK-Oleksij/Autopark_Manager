# Autopark — система керування автобусним автопарком

Вебзастосунок для керування перевізниками, автобусами, маршрутами, водіями та допусками водіїв до маршрутів. Backend: FastAPI + SQLAlchemy + MySQL. Frontend: HTML, CSS і JavaScript без обов’язкового frontend-фреймворку.

> **Статус:** backend надає CRUD для компаній, автобусів, водіїв і маршрутів; frontend ще потрібно реалізувати. Позначки в цьому документі відображають відомий стан роботи, а не повний автоматизований тест.

## 1. Технології

- Python, FastAPI, Uvicorn
- SQLAlchemy, PyMySQL, MySQL
- Pydantic для валідації даних API
- HTML, CSS, JavaScript для frontend
- `fetch()` для HTTP-запитів до API

### Наявні маршрути API за кодом

| Метод | Шлях | Призначення |
|---|---|---|
| GET | `/health` | Стан API |
| GET | `/db-check` | Перевірка з’єднання з MySQL |
| GET | `/companies` | Список перевізників |
| GET | `/companies/{company_id}` | Перевізник за ID |
| POST | `/companies` | Створення перевізника |
| PUT | `/companies/{company_id}` | Повне оновлення перевізника |
| DELETE | `/companies/{company_id}` | Видалення перевізника; `409`, якщо є пов'язані записи |
| GET | `/buses` | Список автобусів |
| GET | `/buses/{bus_id}` | Автобус за ID |
| POST | `/buses` | Створення автобуса |
| PUT | `/buses/{bus_id}` | Повне оновлення автобуса |
| DELETE | `/buses/{bus_id}` | Видалення автобуса |
| GET | `/drivers?limit=10&offset=0` | Сторінка водіїв (`total`, `items`, `limit`, `offset`) |
| GET | `/drivers/{driver_id}` | Водій за ID |
| GET | `/drivers/{driver_id}/routes` | Маршрути, на які призначений водій |
| POST | `/drivers` | Створення водія |
| PUT | `/drivers/{driver_id}` | Повне оновлення водія |
| DELETE | `/drivers/{driver_id}` | Видалення водія та його призначень |
| GET | `/routes` | Список маршрутів |
| GET | `/routes/{route_id}` | Маршрут за ID |
| POST | `/routes` | Створення маршруту |
| PUT | `/routes/{route_id}` | Повне оновлення маршруту |
| DELETE | `/routes/{route_id}` | Видалення маршруту; `409`, якщо є призначення |
| GET | `/driver-routes` | Список допусків/призначень |
| POST | `/driver-routes` | Додати водія на маршрут |
| DELETE | `/driver-routes/{driver_id}/{route_id}` | Скасувати допуск/призначення |

CRUD-сценарії перевірено на ізольованій SQLite базі. Перевірка на MySQL не виконувалася.

`POST` повертає `201`; відсутній ресурс або компанія повертає `404`; повторне унікальне значення повертає `409`; некоректне тіло запиту повертає `422`. `PUT` приймає повний ресурс у форматі відповідної схеми створення й повертає `200`. Успішний `DELETE` повертає `204`.

Для `POST /driver-routes`: якщо водія або маршрут не знайдено, повертається `404`; якщо вони належать різним компаніям — `422`; повторне призначення — `409`. Успішне призначення повертає `201`. Видалення відсутнього призначення повертає `404`, успішне — `204`.

`GET /drivers` за замовчуванням повертає 10 записів від `offset=0`; `limit` має бути від 1 до 100, `offset` — невід'ємним. Список має стабільне сортування за ID, а `total` рахує всі записи, незалежно від поточної сторінки. `GET /drivers/{driver_id}/routes` повертає тільки маршрути з наявними призначеннями цього водія (`404`, якщо водія не знайдено).

Тіло `POST /companies` і `PUT /companies/{company_id}` має містити обидва обов'язкові поля:
```json
{
  "name": "Назва перевізника",
  "phone": "+380..."
}
```

## 4. Frontend: обов’язкові екрани

Frontend має бути реалізований на **HTML + CSS + JavaScript**. Він звертається до FastAPI через `fetch()` і показує користувачу зрозумілі стани та повідомлення.

### 4.1 Головна — `index.html`

- Лічильник перевізників.
- Лічильник автобусів.
- Лічильник маршрутів.
- Лічильник водіїв.
- Посилання на відповідні розділи.
- Індикатор доступності API через `/health`.
- Стани завантаження, помилки та недоступності API.

Для лічильників можна завантажувати списки з API та рахувати отримані записи на початку. Якщо згодом буде багато записів, доцільно додати окремі агреговані endpoints статистики на backend.

### 4.2 Перевізники — `companies.html`

- Таблиця перевізників.
- Стан завантаження, порожній стан, стан помилки.
- Форма створення з валідацією.
- Зрозумілі повідомлення про успіх і помилки.
- За потреби додати редагування та видалення після реалізації відповідних backend endpoints.

### 4.3 Маршрути — `routes.html`

- Таблиця маршрутів.
- Показувати номер, назву, відстань і назву перевізника.
- Стан завантаження, порожній стан, помилка.
- Форма створення з валідацією та вибором перевізника.
- Перевіряти введені дані перед відправленням.

### 4.4 Автобуси — `buses.html`

- Таблиця автобусів із номерним знаком, моделлю, кількістю місць і назвою перевізника.
- Стан завантаження, порожній стан, помилка.
- Форма створення з вибором перевізника.
- Якщо немає перевізників, показувати повідомлення замість порожньої форми.
- Перевіряти поля до відправлення на сервер.

### 4.5 Водії — `drivers.html`

- Таблиця водіїв із даними водія та назвою перевізника.
- Пагінація через `limit` і `offset` на backend; стандартний розмір сторінки — 10, дозволені розміри — 10/20/50.
- Пошук по поточній сторінці.
- Створення водія.
- Редагування водія.
- Видалення водія з підтвердженням.
- Стани завантаження, порожній стан, помилка, дані.
- Якщо перевізників немає, показувати повідомлення замість форми створення.
- Backend має додатково реалізувати пагінацію та PUT/PATCH/DELETE, перш ніж UI зможе повноцінно використовувати ці функції.

### 4.6 Картка водія — `driver.html`

Сторінка відповідає URL-патерну `/drivers/:id` (для статичного frontend це може бути `driver.html?id=123`, якщо не налаштовувати routing).

Показувати:
- ПІБ, телефон, номер посвідчення та назву перевізника.
- Список маршрутів, до яких водій допущений.
- Форму «Додати до маршруту», де доступні лише маршрути тієї самої компанії, до якої належить водій.
- Скасування допуску з підтвердженням.
- Лічильник допусків із правильною формою слова залежно від кількості.
- Порожній стан, завантаження та повідомлення про помилки.

#### Логіка окремих запитів для допусків водія

Рекомендований контракт API для картки водія:

1. `GET /drivers/{id}` — отримати дані водія.
2. `GET /drivers/{id}/routes` — отримати лише маршрути, на які допущений цей водій.
3. `GET /routes?company_id={company_id}` або еквівалентний endpoint — отримати маршрути компанії для форми додавання. Цей фільтр треба реалізувати на backend; зараз він не підтверджений.
4. `POST /driver-routes` з `{ "driver_id": id, "route_id": routeId }` — додати допуск.
5. `DELETE /driver-routes/{driver_id}/{route_id}` — скасувати допуск.

Після успішного POST або DELETE frontend має повторно завантажити список допусків і оновити лічильник. У разі `409` потрібно пояснити, що такий допуск уже існує; у разі `422` — показати причину валідації. Якщо водія не знайдено (`404`), показати стан «Водія не знайдено».

**Пункти 2 і 3 потребують додаткових backend endpoints або підтвердженого фільтрування.** Не слід робити припущення, що ці запити вже працюють.

## 6. CORS

Якщо frontend і backend працюють на різних адресах або портах, наприклад frontend на `http://127.0.0.1:5500`, а API на `http://127.0.0.1:8000`, backend має дозволяти запити з адреси frontend через `CORSMiddleware`. У production потрібно дозволяти тільки потрібні origin, а не всі адреси без потреби.

## 7. Локальний запуск

1. Запустити MySQL і переконатися, що база `autopark_db` доступна.
2. Налаштувати змінну середовища `DATABASE_URL`, наприклад у PowerShell:
   ```powershell
   $env:DATABASE_URL = "mysql+pymysql://<user>:<password>@127.0.0.1:3306/autopark_db?charset=utf8mb4"
   ```
   Не зберігати облікові дані в коді чи Git.
3. Активувати `.venv` та за потреби встановити пакети:
   ```bash
   pip install fastapi uvicorn sqlalchemy pymysql
   ```
4. У папці `api/` запустити:
   ```bash
   uvicorn main:app --reload
   ```
5. Відкрити Swagger: http://127.0.0.1:8000/docs.
6. Запустити frontend через локальний HTTP-сервер (наприклад, Live Server у VS Code), а не покладатися на відкриття HTML як `file://`.
