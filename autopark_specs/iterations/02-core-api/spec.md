# Ітерація 02 — Базові API-ресурси

## Мета
Перевірити й довести до узгодженого стану CRUD API для компаній, автобусів, водіїв і маршрутів.

## Обсяг
- Перевірити методи, шляхи та response_model.
- Перевірити створення, отримання списку, отримання за ID, оновлення й видалення там, де ці операції передбачені проєктом.
- Перевірити Pydantic v2 схеми й валідацію.
- Перевірити відповіді для відсутніх записів і конфліктів унікальності.
- Перевірити, що FK посилаються на наявні компанії.

## Обмеження
- Спочатку скласти матрицю наявних endpoint-ів; не дублювати вже готові.
- Не змінювати реальні дані без явного дозволу.
- Не вигадувати бізнес-поля, послуги чи значення.

## Критерії приймання
- Контракт кожного ресурсу задокументований.
- Успішні та помилкові відповіді мають очікувані статуси.
- Схеми відповіді не повертають неочікувані поля.
- Наявні сценарії не регресують.

## Перевірка
Використати Swagger та безпечні GET/валідаційні запити; для POST/PUT/PATCH/DELETE — тестову БД або погоджені тестові записи.
