# Ітерація 05 — Надійність API

## Мета
Уніфікувати перевірку помилок і поведінку API перед підключенням frontend.

## Обсяг
- Перевірити обробку `IntegrityError` з `rollback`.
- Перевірити валідацію полів і статуси помилок.
- Переконатися, що відповіді не розкривають паролі, DSN або внутрішні трасування.
- Налаштувати CORS лише якщо frontend працює з іншого origin.
- Перевірити OpenAPI-контракти та повідомлення помилок.

## Обмеження
- Не додавати автентифікацію, ролі чи інтеграції без вимоги.
- Не приховувати помилки програмування загальним catch-all без журналювання.

## Критерії приймання
- Очікувані помилки мають стабільні статуси.
- Після помилок БД сесія не залишається в зламаному стані.
- Конфігурація секретів не виводиться в API-відповіді.

## Після завершення
Оновити `progress.md` і зупинитися до підтвердження користувача.
