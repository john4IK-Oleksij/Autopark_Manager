# Autopark — Mission

## Незмінна мета
Створити вебзастосунок для керування автопарком автобусів: компаніями, автобусами, водіями, маршрутами та призначеннями водіїв на маршрути.

## Предметна модель
- **Company** — транспортна компанія.
- **Bus** — автобус, належить одній компанії.
- **Driver** — водій, належить одній компанії.
- **Route** — маршрут, належить одній компанії.
- **DriverRoute** — призначення водія на маршрут; пара `driver_id + route_id` унікальна.

### Бізнес-правила
- Водій і маршрут у призначенні мають належати одній компанії.
- Не можна створювати дублікати унікальних значень, визначених схемою БД.
- Під час видалення водія його призначення можуть видалятися каскадно.
- Видалення маршруту, на який є призначення, має бути заборонене, якщо так налаштовано зовнішній ключ БД.
- API повертає зрозумілі HTTP-статуси й повідомлення про помилки.

## Технології
- Backend: Python, FastAPI, SQLAlchemy 2.0 typed ORM (`Mapped`, `mapped_column`), Pydantic v2.
- База даних: MySQL.
- Frontend: HTML, CSS, JavaScript без обов'язкової frontend-фреймворк-залежності.
- API-документація: FastAPI Swagger UI (`/docs`).

## Загальні архітектурні обмеження
- Розділяти моделі, схеми валідації, залежності, роутери й налаштування БД за призначенням.
- Не змішувати HTTP-логіку з SQL-запитами без потреби.
- Для SQLAlchemy використовувати сучасний typed ORM стиль послідовно в усіх моделях.
- Не змінювати схему БД або наявні дані без потреби; перевіряти відповідність моделей фактичній структурі БД.
- Не додавати фальшиві дані про компанії, тарифи, адреси, контакти чи послуги.
- Валідувати введення на межі API.
- Уникати небезпечного вставлення користувацького тексту в DOM; на фронтенді віддавати перевагу `textContent`.
- Інтерфейс має бути адаптивним і підтримувати вузькі екрани від 360 px.
- Зберігати робочий код попередніх ітерацій; рефакторити його лише за обґрунтованої потреби.

## Візуальний напрям
Використовувати яскраву, сучасну палітру з насиченими зеленими, рожевими, блакитними та спорідненими акцентами. Не вважати попередні приглушені значення кольорів обов'язковими. Конкретні кольори й контрастність визначати в окремій UI-ітерації та централізувати в CSS custom properties.

Загальний характер: чистий, дружній, енергійний інтерфейс; білі картки з радіусом близько 20 px, легкою тінню й достатнім внутрішнім простором. Шрифт — Manrope із запасним системним sans-serif.

## Spec-Driven Development
- `mission.md` описує сталі цілі, предметну модель, технології та загальні обмеження.
- `roadmap.md` визначає порядок малих ітерацій.
- Кожна ітерація має власний `spec.md` у відповідній теці.
- Не переходити до наступної ітерації, доки поточну не реалізовано й не перевірено за критеріями приймання.
- Перед змінами перевіряти наявний код і повторно використовувати те, що вже працює.
- Після кожного етапу фіксувати результат, перевірки та відомі проблеми в `progress.md`.
